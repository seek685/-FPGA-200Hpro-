本轮改动

保留五级单发射结构和 myCPU 外部端口，改动 7 个 RTL 文件：

* branch_predictor.sv：保留 4096 项两位 gshare 和 512 项 BTB，增加 16 项返回
  地址栈，支持 x1/x5、嵌套调用和 coroutine。JAL 在 IF 直接算目标；JALR 优先
  使用返回栈，其余使用 BTB。只让条件分支训练方向表和推进历史。
  返回栈只接受 EX 已确认指令更新，并向 IF 旁路当拍 push/pop，避免错误路径
  调用污染栈。BTB/PHT 依赖 FPGA 配置初始化，软复位保留训练；EX 校验错误目标。
* myCPU.sv：JAL/JALR 仅在预测错误时恢复；JALR 使用独立目标加法器，避开通用
  ALU 选择链。增加 MEM 加载结果到 EX 存储数据的专用旁路，并正确处理分支历史
  恢复优先级。PC 仍保留重定向优先于停顿的原有保护。
* hazard_detection.sv：去除仅依赖 store 数据的 load-use 停顿；store 地址、
  普通 ALU、分支和 JALR 对加载结果的依赖仍保留必要停顿。
* if_id.sv / id_ex.sv：冲刷只取消 valid，避免恢复信号驱动宽数据通路清零。
  全局复位仍初始化状态；寄存器写、总线写和预测训练均受有效位控制。
* branch_unit.sv：共享相等比较，分段并行实现大小比较，缩短分支恢复组合链。
* regfile.sv：仅将循环变量移到模块作用域，以兼容 PDS ADS 编译器。

LUTRAM 已包含在总 LUT 中，不能再次相加。总 LUT 增加 223（8.95%），FF 增加 11。
两版均满足约 150 MHz 的纯核内部 setup/hold 约束，尚无显著提频证据。
最终 setup 首关键路径为 PC -> BTB 标签读取与匹配 -> next_pc -> PC。

另测 rev4 简化 PC 停顿使能，周期相同且少 17 LUT/5 FF，但路由后 setup 余量
为 +0.180 ns。考虑用户重视性能和稳定性，最终选取余量较大的 rev3；rev4 结果
作为对照保留，不是当前根目录 RTL。单次布线结果仍有布局波动，不能视作最优上限。

这是独立 CPU 的实现：自动分配 IO，仅约束 CPU 时钟，未设数据输入/输出延迟，
不包含真实 IROM、BRAM、外设顶层、NPU 或共享互连。报告中的内部周期估计不能
视为 200Pro 整板 Fmax，尤其不能覆盖新增访存旁路跨越的实际 BRAM/桥接路径。

本版优先同频绝对吞吐，并非所有比赛指标同时最优。按本次 CoreMark 计时周期和
总 LUT 粗略归一，同频性能/LUT 比原版约下降 2.84%；它不是正式 CoreMark/LUT
分数。比赛若更看重资源效率，应结合实际评分权重选择，而不能只看周期降低。

使用边界与后续衔接

本轮交付是 CPU RTL 性能升级，尚未接入 NPU，也未生成或下载 200Pro 整板位流。
原顶层 top.sv / student_top.sv 随源保留，仍引用原工程 PLL/IROM/BRAM IP；它们
不是已经迁移完成的 200Pro 顶层。纯核 PDS 脚本以 myCPU 为顶层。
当前取指需要组合读，数据接口需要固定一拍响应。对接共享 DDR、仲裁总线或
可变延迟 NPU 互连时，必须补访存握手，并重新验证桥接和时序；不能直接套接。
新增 load -> store 旁路跨过数据返回边界，整板实现需要包含真实 BRAM/桥接路径。

剩余主要性能限制是 PC -> BTB 读取/标签匹配 -> next_pc 路径、连续嵌套返回、
多目标间接跳转及普通 load-use 停顿。返回栈本轮采用 EX 确认更新，避免引入
投机栈回滚的复杂度。完整 Cache、异常/中断和 NPU 异构调度不在本轮改动中。
